Slide 1 – Problem Statement
Lack of transparency and verifiability
Existing e-voting systems do not let voters independently verify their votes.
Centralized, vulnerable infrastructure
Election data stored in traditional centralized databases.
Single point of failure; susceptible to hacking and unauthorized modifications.
Inefficient verification
Manual audits are time-consuming, error-prone, and costly.
Core challenge
Design a system that guarantees one-person-one-vote while preserving data integrity and trust.
Slide 2 – Objectives
Design a secure, transparent E-voting system using blockchain.
Prevent vote tampering and duplicate voting via smart contracts.
Enable immutable, verifiable vote storage on a distributed ledger.
Reduce reliance on centralized authorities for counting and verification.
Provide a simple, user-friendly interface for voters and administrators.
Showcase a real-world governance application of blockchain technology.
Slide 3 – Existing System & Disadvantages
Centralized e-voting infrastructure
Data stored in traditional databases controlled by authorities.
Limited transparency
Voters cannot independently verify correctness of results.
Operational issues
Manual audits required to gain confidence in results.
High operational and verification costs.
Security concerns
Single point of failure.
Vulnerable to hacking, data manipulation, and insider threats.
Result
Lack of voter trust and difficult independent auditing.
Slide 4 – Proposed System & Advantages
Decentralized blockchain-based voting
No single point of failure; data replicated across nodes.
Smart contracts
Encapsulate voter registration and voting logic.
Automatically enforce election rules (phases, eligibility, one vote per user).
Immutable vote storage
Votes stored as blockchain transactions; tampering is detectable.
Transparent and auditable
Anyone can verify tallies on-chain.
Reduced manual work
Automated result computation and integrity checks.
Improved security
Strong cryptography, tamper-proof ledger, higher voter trust.
Slide 5 – System Architecture / Flow
User Interface / Web Pages
Registration, voting, verification, results dashboards.
Backend (Node.js + Express)
REST APIs for register, vote, verify, and results.
Validation of inputs and eligibility.
Smart Contract (Solidity)
Manages phases: Registration → Voting → Ended.
Stores voter and candidate state.
Local Blockchain Network (e.g. Ganache)
Executes contract code and stores vote transactions.
High-level Logic
UI → Express API → Smart Contract → Blockchain.
If user already voted, contract denies and API returns “vote denied”.

Slide 7 – MODULE 1: User Interface Module
Purpose
Provide a secure, intuitive front-end for voters, admins, and auditors.
Key Responsibilities
Present registration, voting, verification, and result views clearly.
Validate user input before sending data to backend/blockchain.
Handle user feedback: success messages, error alerts, and confirmations.

(Optional) multi-language support.
Accessibility-aware layouts and controls.
Technology Stack
Web: HTML, CSS, JavaScript.
Styling: Modern CSS/glassmorphism (or TailwindCSS if you mention it).
Integration: Express REST APIs, ethers.js, Ganache.
MODULE 2 – Voter Registration Module
Slide 8 – Module 2: Overview
Purpose
Onboard eligible voters and ensure only valid identities can cast votes.
Map each citizen to a unique blockchain wallet address.
Scope
Initial enrollment before any voting occurs.
Enforces “one-person-one-account” at the registration stage.
System Components
Registration UI screen.
/api/register backend API.
Smart contract function: registerVoter(address).
Slide 9 – Module 2: Core Flows
New Voter Registration
User enters wallet address and optional identity details.
Backend validates:
Correct wallet format.
Wallet not already registered.
Registration phase is open.
Smart contract sets voters[wallet].registered = true.
Controlled Updates
Optional updates to non-critical off-chain profile fields.
De-duplication & Fraud Checks
Duplicate wallets rejected (“Voter already registered”).
One on-chain identity per voter to prevent impersonation.
Slide 10 – Module 2: Security & Implementation
Security & Compliance
Registration allowed only during Registration phase.
Optional KYC/ID details kept off-chain with secured APIs and audit logs.
Error Handling
Friendly messages for:
Closed registration (“Registration is closed. Voting has already started.”).
Duplicate wallet (“This wallet is already registered.”).
Missing or invalid wallet.
UI Implementation
Split screen registration:
Left: form for wallet + name + ID.
Right: biometric “face scan” demo interface (no real AI, only UX).
Backend/Contract
Express route → voting.service.registerVoter() → Voting.registerVoter.
MODULE 3 – Voting Module
Slide 11 – Module 3: Overview
Purpose
Allow registered voters to cast ballots securely and anonymously via blockchain.
Responsibilities
Show live candidates retrieved from the contract.
Accept a registered wallet and candidate selection.
Submit vote as a blockchain transaction.
UI
“Cast Your Vote” page with:
Wallet field at top.
Candidate cards (name + ID).
Status messages for success/errors.
Slide 12 – Module 3: Voting Flow & Validation
Voting Flow
Step 1: Voter enters or confirms wallet address.
Step 2: Application fetches candidate list from smart contract.
Step 3: Voter clicks a candidate card to cast their vote.
Validation Rules
The wallet must:
Be registered (voters[wallet].registered == true).
Not have voted before (hasVoted == false).
Election must be in Voting phase (set by admin).
Candidate ID must be valid.
User Feedback
On success:
“Vote for \<candidate\> recorded successfully” and UI disables further votes.
On error:
Clear messages for “not registered”, “already voted”, “voting not active”, or invalid candidate.
Slide 13 – Module 3: Security, Reliability & Tech Stack
Security
Smart contract enforces:
One vote per registered wallet.
No voting outside the valid phase.
No invalid candidate IDs.
All votes stored immutably on blockchain.
Reliability
Frontend maps technical errors (revert messages) to readable text.
Handles network/transaction failures and shows retry guidance.
Technology Stack
Frontend: HTML, CSS, JavaScript (modern, responsive vote UI).
Backend: Node.js + Express (/api/vote).
Blockchain: Solidity Voting.castVote(uint256) on local Ethereum (Ganache) via ethers.js.
Slide 14 – MODULE 4: Vote Verification Module
Purpose
Allow voters to verify that their vote is recorded on the blockchain.
Responsibilities
Accept wallet address as input.
Query on-chain voter state: registered / hasVoted.
Display a simple confirmation status (no vote contents revealed).
Verification Flow
Voter enters the wallet they used to vote.
Backend /api/verify calls:
isRegistered(wallet) and hasUserVoted(wallet).
UI shows:
CONFIRMED if hasVoted == true.
NOT FOUND if no vote is recorded or wallet not registered.
Slide 15 – MODULE 5: Result Management Module
Purpose
Compute, display, and manage election results in a transparent way.
Responsibilities
Aggregate votes per candidate from the contract.
Show total votes and per-candidate counts on the UI.
Optionally allow admins to end the election phase.
Features
Live results view:
Candidate names, vote counts, and percentage bars.
Read-only after voting ends:
No modification of on-chain results.
Consistency checks:
Total votes from /api/status match totalVotes from /api/results.
Slide 16 – Conclusion
Summary
Blockchain-based E-voting addresses transparency, integrity, and trust issues.
Key Benefits
Decentralization removes single points of failure.
Smart contracts enforce election rules automatically.
Immutable ledger enables independent verification and auditing.
Outcome
Prototype demonstrates practical feasibility of blockchain in electoral systems.
Provides a foundation for future large-scale or national-level deployments.
